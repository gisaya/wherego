## 사용량 정책

- 기본 1회/일, 매일 첫 추천은 전면·배너 광고 없이 제공
- 리워드 광고 시청 완료마다 +1, 일일 광고 횟수 제한 없음. 보상 크레딧에는 두 번째 전면광고를 표시하지 않음
- 친구 공유 +3, 하루 1회
- 신규 이용권 판매 제거. 기존 미사용 유료 횟수와 저장 로그인 세션의 주문 복원/환불 확인은 유지
- KST 자정에 일일 항목만 초기화
- 일반 후보 준비 예약, 성공 확정, 실패 환불, 중복 세션 멱등 처리. 광고 경로의 후보 미리보기는 예약·차감 없음

정책의 단일 원본은 JBG 서버 응답이다. 클라이언트 숫자는 서버가 로딩되기 전의 동일한 안내값일 뿐이다.

2026-10-01 정책·프롬프트·비공개 준비 서버 배포를 확인했다. 새 AIT는 `usagePolicy=uncapped-v1`으로 무제한 한도 `adRewardsLimit: null`을 처리한다. 구 AIT에는 실제 상한 대신 다음 광고 허용 수치와 `adRewardsUnlimited: true`를 반환하는 호환 처리가 배포됐다. DB 마이그레이션은 없다. 사용자가 실기기 검증·토스 버전 등록 완료를 보고했으며 검토 승인·실제 출시 상태는 별도로 확인하지 않았다.

광고는 6문항 뒤에 요청하며 실제 `impression` 후 20초에 비공개 선택을 준비한다. 보상이 먼저 오면 서버 지급 직후 추천한다. 보상·서버 크레딧·광고 종료 확인 전에는 결과를 표시하지 않는다. AI 시작 이후 미완료 비용, 프로세스 로컬 10분 캐시의 재시작·만료·다중 인스턴스 한계를 실제 청구액에 반영한다. 상세는 `MINIAPP_GROWTH_UX.md`를 따른다.

## 프로모션 운영

- 혜택 placement는 반드시 `/promotion`으로 등록한다.
- 일반 `/`에서는 혜택 문구와 프로모션 지급 API 호출이 없어야 한다.
- JBG는 `getAnonymousKey()` hash를 mTLS 검증하고 지급 key 발급과 실제 50원 지급을 수행한다.
- 서버 guard가 사용자 hash와 프로모션 코드 조합을 원자적으로 예약한다.
- 검증·지급 key 발급 전 실패만 안전하게 해제한다. 실제 지급 요청 결과가 불명확하면 중복 방지를 위해 예약을 유지한다.
- `/api/wherego/promotion/attempt`는 이전 출시 AIT 호환용으로 제거하지 않는다.

## 기존 인앱결제 주문 유지

- 신규 판매는 `enabled: false`이며 구매 UI·상품 목록·가격 조회를 제거했다. 운영 콘솔 상품 상태도 확인한다.
- 기존 주문 검증용 SKU는 삭제하지 않는다. `restorationEnabled`는 기존 주문 복원 가능 여부이며 신규 판매를 활성화하지 않는다.
- Render는 로그인 secret과 mTLS 인증서를 사용해 주문을 검증한다.
- 유료 이용권 잔액이 있거나 마지막 유료 추천을 진행 중이면 배너광고가 노출되지 않는다.
- 주문 ID 기준 중복 지급을 막고 pending 주문 복원과 환불 회수를 수행한다.
- 인증서 원문과 private key는 Render secret에만 둔다.

3. 루트·서비스 약관·개인정보 페이지와 대표 결과 이미지 URL의 HTTP 200 확인

## 자동 QC

사용자 QC 지시는 최근 12시간 표본과 10건 미만일 때 보조 24시간, 한국시간 월요일 00:00~02:59 첫 실행의 7일 검토다. 실제 일정은 저장된 자동화 설정이 기준이며 이번 저장에서 변경하지 않는다.

- 성공/실패와 후보 0건
- Gemini fallback
- 이미지·지도 누락
- 새 앱 6문항·원천3+일반3, 구 앱 7문항 계약과 구성
- 후보 5~7개
- 거리·지역 위반
- p95 지연
- 관광지·지역·검색 키워드 집중
- 답변과 추천/근거의 의미 불일치

원시 QC JSON, 사용자 해시, 세션 원문, DB 접속정보는 외부에 노출하지 않는다.

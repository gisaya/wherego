# 검증

최종 갱신: 2026-10-01 KST

명령 원문은 루트 `RUNBOOK.md`를 따른다. 이 문서는 변경 유형별 합격 기준만 정의한다.

## 모든 앱 변경

- Jest 단위 테스트 통과
- TypeScript strict 검사 통과
- `git diff --check` 통과
- 비밀값, `TEST_` 코드, 생성물 미추적 확인
- 일반 `/`과 혜택 `/promotion`의 조건 분기 검토

## UI 변경

- Android 실기기에서 2지선다와 4지선다 카드 선택 가능
- 긴 질문·선택지·번호·작은 문구가 잘리지 않음
- 2지선다·4지선다 전환에도 질문 배너가 별도 하단 영역에 있고 안전영역·버튼·카드와 겹치지 않음
- 초기 이용정보 로딩 중 인트로 중간 상태가 노출되지 않고 완료 뒤 화면이 한 번만 나타남
- 성공 결과 2회 이상에서 리뷰 CTA가 한 번만 나타나며 닫힌 뒤 다시 노출되지 않음
- 제출 전 뒤로가기는 이전 단계와 선택 답변으로 복귀하고 제출 이후·홈에서는 종료 확인이 동작
- 공유 버튼 위 간격, 한 줄 공유 안내, 찜·공유 수신·현재 위치 재시도 확인
- 화면 저장 PNG가 1080x1350 비율이고 이미지·위치·AI 근거가 잘리지 않음

## 질문 또는 추천 변경

- 서버 Wherego 테스트 전체 통과
- 새 앱의 `questionCount: 6`은 원천 3 + 일반 3. 이전 앱의 기본 7문항 계약도 호환 유지
- 한 세트 내부 질문 ID와 의미 테마 중복 0
- 모든 선택지가 검색 가능한 메타데이터를 가짐
- 전체 선택 메타데이터를 반영하고 소프트 선호와 명시적 필수 거리/지역/이용 가능·안전 조건을 구분함
- 후보는 정상 흐름에서 5~7개, 최종 추천은 1개
- 후보 0개에서도 Gemini `direct`가 호출되고 관광공사·하드 제약 재검증 뒤 성공하거나 질문 재선택으로 종료됨
- 명시적 필수 지역·거리 조건 위반 0. 소프트 거리·혼잡도·분위기의 단일 단계 차이는 결함으로 단정하지 않음
- Gemini 직접 제안은 관광공사 정확 일치 결과가 있으면 기존 거리·지역·반려동물 제약을 통과해야 함
- 관광공사 미등록 자체 추천은 `source=gemini`, `ktoVerified=false`이고 운영·시설 정보를 만들지 않음
- 대표 이미지가 없으면 컨셉 공통 이미지와 실제 사진 없음 문구가 화면·저장 PNG에 함께 표시됨

질문 JSON만 변경했으면 서버 배포와 API 확인으로 충분하며 AIT를 만들지 않는다.

## 광고 변경

- 출시 소스와 AIT에 라이브 ID만 존재
- 질문 배너, 결과 전 전면광고, 횟수 충전 리워드 광고의 역할이 섞이지 않음
- 리워드 횟수는 `userEarnedReward` 이후에만 지급
- 매일 첫 무료·기존 유료 크레딧은 전면·배너 광고 생략. 광고 보상 크레딧에는 두 번째 전면광고 없음. 공유 크레딧의 기존 정책 유지
- 잔여 0회에도 6문항을 먼저 선택하고 미리보기에서 AI·차감·예약 없음
- 보상 광고 `show`/요청만으로 AI를 시작하지 않음. 실제 `impression` 후 20초에 비공개 준비하며 빠른 보상은 타이머 취소 후 서버 지급 직후 추천
- 종료/실패/이탈 시 타이머 취소, 중복 이벤트·재시도 단일 처리, 보상·서버 지급·광고 종료 전 결과 차단
- 20초 뒤 AI 시작 후 광고 미완료 비용 가능성을 기록. 캐시 재시작·만료·다중 인스턴스 한계와 정산 증거 미검증을 구분
- 당일 3회 이상 광고에서도 +1씩 계속 지급하고 예전 유한 상한·표시 실패에서는 답변을 유지한 복구/재시도 제공

- 일반 진입에서 프로모션 지급 API 호출 0
- 혜택 진입 최초 성공 결과에서만 50원 지급
- 서버 guard 예약 또는 식별키 검증 실패 시 포인트 지급 0
- 재렌더, 재진입, 재설치에 중복 지급 0

- 운영 AIT에 테스트 코드 없음

## 기존 인앱결제 복원

- 신규 구매 UI·상품 조회·새 로그인/주문 생성 호출 없음
- 기존 유료 잔여 유지, 유효한 저장 로그인 세션의 과거 주문만 복원
- 기존 주문 지급은 서버 SKU 정책에 맞춰 정확히 1회. 신규 판매 활성화 없음
- pending 복원, 취소 미지급, 중복 주문 미지급, 환불 회수
- 앱 재실행 후 기존 잔여 유지. 세션 만료·기기 변경은 문의 안내로 처리하고 새 로그인 모달 없음

## 서버 배포 후

- `/api/health`가 새 JBG commit과 Postgres 정상 상태를 반환
- `/api/wherego/questions`가 새 앱 요청에 6문항(원천3+일반3)을 반환하고 기존 7문항 계약 유지
- `/api/wherego/usage`가 `usagePolicy=uncapped-v1`에서 `baseDailyLimit: 1`, `adRewardsLimit: null`을 반환. 구 앱에는 다음 광고 허용 수치와 `adRewardsUnlimited: true`를 제공
- 광고 시청 완료마다 1회 지급. 보상 미획득·중복·표시 실패에서는 미지급/결과 차단. 노출 20초 후 비공개 AI 실행은 미완료 비용과 별도로 평가
- `/api/wherego/prepare-selection`은 결과·크레딧을 공개하지 않으며 미리보기/준비의 잘못된 입력은 HTTP 400으로 차단
- IAP products는 신규 판매 `enabled: false`, 기존 주문 `restorationEnabled` 상태 반환
- 추천 smoke가 이미지·지도와 최종 1개를 반환

## QC 기준

사용자 지시는 최근 12시간을 보고 10건 미만이면 24시간을 추가하며, 한국시간 월요일 00:00~02:59 첫 실행에만 168시간을 추가하는 것이다. 실제 일정은 저장된 자동화 설정이 기준이고 이번 저장에서 변경하지 않는다.

- 성공/실패율과 후보 0건
- Gemini fallback
- 이미지·지도 누락
- AI 자체 추천 횟수·비율과 공통 이미지 연결 여부
- 새 앱 6문항·원천3+일반3 및 이전 앱 7문항 계약 구분
- 후보 압축 범위
- 거리·지역 제약 위반
- p95 전체/KTO/Gemini 지연
- 특정 관광지·지역·검색 키워드 집중도
- 답변과 최종 장소·AI 근거의 의미 일치

주간 표본 10건 미만에서는 편향을 단정하지 않는다.

이미 수정·배포된 과거 기록은 새 이상으로 반복 보고하지 않는다. 생성형 설명은 계산 거리·주소·명시적 부정 정보·이용 불가·안전 조건과 객관적으로 충돌할 때만 결함으로 판단한다.

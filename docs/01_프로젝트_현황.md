# 프로젝트 현황

최종 갱신: 2026-10-01 KST

## 제품

`주말어디`는 사용자가 6개의 선택형 질문에 답하면 한국관광공사 관광정보와 지역별 방문자수 데이터를 바탕으로 AI가 국내 관광지 1곳을 추천하는 Apps in Toss 미니앱이다. 내부 앱 식별자는 `wherego`를 유지한다.

핵심 가치는 성격 테스트가 아니라 실제로 갈 목적지를 빠르게 좁히는 것이다.

## 사용자 흐름

1. 일반 `/` 또는 혜택 `/promotion` 진입 후 횟수·저장 로그인 조회. 유효한 저장 세션의 기존 주문만 뒤에서 복원
2. 현재 위치나 직접 선택 지역으로 출발 기준 설정
3. 잔여 횟수와 무관하게 서버 질문 6개에 카드 방식으로 답변
4. 서버가 KorService2/DataLab 후보 준비. 잔여 0회면 AI·차감 없는 미리보기 사용
5. 매일 첫 무료·기존 이용권은 바로 추천. 추가 추천은 답변을 유지한 채 사용자가 보상 광고 버튼을 누름
6. SDK 노출 확인 후 20초에 비공개 AI 선택 준비. 보상이 먼저 오면 서버 지급 직후 추천 시작. 후보가 0개면 직접 제안 후 관광공사 재검증
7. 보상·서버 크레딧·광고 종료 확인 뒤 결과 표시. 친구 공유·찜·PNG 저장·네이버지도 제공

광고가 닫혔는데 AI 응답이 남아 있으면 전용 분석 화면을 표시한다. 일시 API 실패만 같은 세션으로 재시도하고, 검증 후보가 없으면 출발지를 유지한 채 새 질문을 고른다.

## 질문 정책

- 원천 3개: 이동 범위, 동행/제약, 목적지 의도
- 일반 3개: 서로 다른 검색 영향 테마. 새 앱은 별도의 재미 문항 1개를 추가하지 않는다.
- 한 세트 안에서 질문 ID와 의미 테마가 중복되지 않는다.
- 이전 앱의 7문항 응답 계약은 호환용으로 유지한다. 질문 세부 가중치는 서버 리소스를 기준으로 확인한다.
- 질문 카피와 메타데이터는 서버 리소스만 수정한다.

세부 정책은 `10_선택지_질문풀_검토.md`를 따른다.

## 추천과 데이터

- 관광정보: 한국관광공사 국문 관광정보 서비스_GW `KorService2`
- 지역 방문 신호: 한국관광공사 빅데이터 지역별 방문자수_GW `DataLabService`
- 최종 선택: `gemini-3.1-flash-lite`
- 지도: 네이버지도 검색 링크
- 이동 시간: 직선거리 기반 추정치이며 길찾기 API 결과가 아니다.
- 최소 거리 하한이 있으면 검색 범위를 전국으로 넓힌 뒤 거리 필터를 적용한다.
- 방문자수는 지역 단위 참고 신호이며 실시간 장소 혼잡도로 표현하지 않는다.

## 횟수와 수익화

- 기본 AI 추천: KST 매일 첫 1회, 전면·배너 광고 없이 제공
- 리워드 광고: 시청 완료마다 +1회, 일일 횟수 제한 없음
- 친구 공유: +3회, 하루 1회
- 신규 인앱결제 판매 제거. 기존에 구매한 미사용 이용권은 보유 횟수를 유지한다. 저장 로그인 세션이 유효하면 기존 미지급 주문 복원과 환불 확인을 계속한다.
- 일일 크레딧을 먼저 사용하고 유료 크레딧을 나중에 사용한다.
- 첫 기본·유료 크레딧에는 결과 전 전면광고를 생략하고, 광고 보상 크레딧에는 두 번째 광고를 노출하지 않는다. 공유 크레딧의 기존 광고 정책은 유지한다.
- 첫 기본 추천 진행 중 또는 유료 이용권 잔액이 있거나 유료 횟수로 진행 중이면 질문·로딩·결과 배너를 생략한다.

정책·프롬프트·비공개 준비 서버는 Render 배포를 확인했다. 새 AIT는 로컬 빌드만 완료했으며 사용자가 직접 등록한다. 준비 후 광고 중도 종료에는 AI 비용이 발생할 수 있다. 상세 한계는 `MINIAPP_GROWTH_UX.md`를 따른다.

공개 웹 실험은 편집된 13개 장소와 10개 상황별 글을 제공하며 AI·JBG 추천·로그인·결제·광고 SDK를 호출하지 않는다. 공개 배포·사진 권한·검색 등록과 수익 검증은 별도 단계다.

## 프로모션

- 일반 진입 `intoss://wherego`는 프로모션을 실행하지 않는다.
- 혜택 진입 `intoss://wherego/promotion`에서만 결과 프로모션을 실행한다.
- 최신 AIT는 사용자 hash를 JBG에 보내고, JBG가 mTLS 식별키 검증과 프로모션 서버 지급을 수행한다.
- 이전 출시 AIT의 클라이언트 지급 guard endpoint는 호환을 위해 유지한다.
- 운영 혜택은 토스 포인트 50원, 1인 1회다.
- 로컬 Storage, 세션 중복 방지, 서버 원자적 예약을 함께 사용한다.
- 서버 예약·식별키 검증 장애 시 포인트를 지급하지 않는 fail-closed 정책이다.

## 앱 화면

- TDS Provider, Text, Button을 기본으로 사용한다.
- 선택 카드와 지역 카드는 고정 크기 `Pressable`로 구현한다.
- 2지선다는 2열 카드, 4지선다는 2x2 카드다.
- 질문 배너는 별도 하단 영역을 사용하고 안전영역·카드와 겹치지 않게 한다. 첫 무료·기존 이용권에서는 숨긴다.
- 첫 화면은 횟수·저장 로그인 조회 뒤 한 번에 표시한다. 상품 조회는 없고 유효한 저장 세션의 기존 주문만 화면 표시 뒤 복원한다.
- 성공 결과 2회 이상 사용자에게 한 번만 앱 리뷰 요청 CTA를 표시한다.
- 저장 카드는 1080x1350 PNG이며 공유 API를 호출하지 않는다.
- 제출 전 뒤로가기는 이전 선택 단계로 돌아간다. 제출 이후와 홈의 종료 확인은 별도로 처리한다.

## 출시 전 남은 확인

1. 일반/혜택 진입을 각각 QR 테스트한다.
2. 프로모션 1회 지급과 중복 방지 실패 시 미지급을 확인한다.
3. 첫 무료·광고 보상 무제한·20초 비공개 준비·미완료 결과 차단·공유·기존 주문 복원을 실기기에서 확인한다. 새 구매 UI는 없어야 한다.
4. 공유 수신·찜·현재 위치·PNG·이미지·지도·하단 배너·리뷰·단계별 뒤로가기를 최신 Toss 앱에서 회귀한다.
5. 저장된 QC 자동화 일정과 보조 표본으로 추천 실패와 의미 일치를 관찰한다. 표본 부족과 해결된 과거 이상을 새 결함으로 집계하지 않는다.

# 주말어디 첫 웹 실험

## 범위와 비용

- 공개 웹은 서울·경기·인천의 편집된 13개 장소에서 브라우저 규칙으로 최대 3곳을 고른다. AI, jbg 추천 API, 로그인, 위치 권한, 결제, 광고 SDK를 호출하지 않는다.
- 지역과 실내·야외 선택을 지킨다. 자연·문화·물가와 걷는 양은 선호 점수이며 덜 맞는 후보에는 주의 문구를 붙인다.
- 광고 수익이 실제로 확인되기 전에는 웹 AI를 추가하지 않는다. 승인만으로 손익이 검증되었다고 보지 않는다. 도입 시 실측 AI 원가, 광고 실수령액, 호출 상한, 월 예산과 차단 장치를 별도 승인한다.
- AI 사용료는 발생하지 않지만 호스팅 트래픽과 이벤트 함수·로그 비용까지 무료라는 뜻은 아니다. 유료 플랜이나 예산 설정은 자동 변경하지 않는다.
- 웹은 토스 미니앱과 별도 실험이다. 미니앱의 현재 AI·광고·기존 이용권·프로모션 정책은 `MINIAPP_GROWTH_UX.md`를 따른다. 앱 식별자는 `wherego`, 표시 이름은 `주말어디`다.

## 첫 유입 실험

- 10개 상황별 글, 13개 장소별 공유 페이지와 sitemap을 제공한다. 순위·검색 유입·광고 승인은 보장되지 않는다.
- 공개 배포 및 검색 등록이 끝난 날부터 4주를 첫 관찰 기간으로 삼는다. 외부 유입이 거의 없으면 추천 품질보다 노출 경로가 아직 검증되지 않은 상태로 판단한다.
- 유입은 검색 노출·클릭, 활용은 지도 열기·저장, 확산은 공유 링크로 들어온 방문을 나누어 본다. 단순 공유 버튼 클릭을 실제 신규 유입이나 예약으로 집계하지 않는다.
- 첫 4주에 검색 클릭이 없으면 글의 검색 의도와 색인 상태를 점검한다. 방문은 있지만 지도·저장이 없으면 장소 구성과 결과 화면을 보완한다. 유입 표본이 적은 동안 유료 광고나 AI 비용을 늘리지 않는다.
- 직접 영업을 전제로 한 숙소 제휴는 범위에서 제외한다. 광고는 향후 실제 트래픽을 확인한 뒤 별도 적용한다.

## 계측의 한계

`/api/events`는 `visit`, `start`, `result`, `place_view`, `map`, `save`, `share`, `share_visit`와 유입 범주만 기록한다. 사용자·세션 ID, 답변, 정밀 위치, 원본 referrer는 보내지 않는다. DNT 사용자는 전송하지 않는다.

이 수치는 **이벤트 발생 수**다. 사용자 수, 재방문율, 사용자별 전환율로 해석할 수 없다. 여러 페이지를 열면 방문 이벤트가 여러 번 생기며 클라이언트 이벤트는 누락·조작될 수 있다. 호스팅 로그만으로 장기 보존과 정확한 퍼널 분석이 완성된 것은 아니다.

Vercel 로그 보존 기간 안에 해당 기간의 로그를 내보내고 다음 명령으로 집계한다. 입력은 한 줄당 JSON 형식이며 이벤트 JSON 자체 또는 `message`에 이벤트 JSON이 든 행을 지원한다. 다른 형식은 `ignored`에 포함되므로 실제 export 형식을 확인한다. 집계 출력에는 원시 로그를 포함하지 않는다. 중복 기간을 겹쳐 집계하지 않는다.

```powershell
node scripts/report-weekend-events.mjs C:\private-reports\weekend.ndjson
```

검색 유입 평가는 Google Search Console·네이버 검색 도구 등록과 권한 연결이 별도로 필요하다. 보존형 분석 서비스나 유료 custom events는 아직 연결하지 않았다.

## 실행과 검증

```powershell
yarn install --immutable
yarn web:build
yarn web:test
yarn web:dev
```

로컬 주소는 실행 출력의 URL을 사용한다. 기본 포트는 4173이며 사용 중이면 다음 포트를 쓴다. Playwright와 Chrome이 있는 환경에서는 `node scripts/verify-weekend-web.cjs`로 데스크톱·모바일, 모든 장소·글, 이미지, 저장·공유, AI 요청 없음과 브라우저 오류를 검증한다. 필요하면 `WEB_BASE_URL`, `BROWSER_CHANNEL`, 외부 제공 Playwright의 `NODE_PATH`를 지정한다.

토스 검증: `yarn test`, `yarn typecheck`, `yarn ait:build`. 산출물은 `wherego.ait`다. 빌드 성공은 실제 기기의 토스 광고·결제·권한·닫기 동작 통과를 의미하지 않는다.

## 공개 전 확인

1. 작업 브랜치 변경을 검토하고 통합한다. 원본 작업 폴더의 기존 변경은 건드리지 않는다.
2. 기존 `wherego` Vercel 프로젝트의 인증·권한을 확인한다. 이전 점검에서 CLI 인증 문제가 있었으며 이번 계측 작업에서도 공개 배포는 실행하지 않았다.
3. `yarn web:build` 결과를 배포한다. 구형 `terms:build`는 약관 전용이므로 새 웹 배포에 사용하지 않는다. 배포 후 공개 도메인의 추천, 이벤트, 약관, 공유, 404, sitemap을 재검증한다.
4. 사진은 공식 관광 페이지에서 제공하는 외부 URL로 표시하며 출처를 링크했다. 실제 서비스 공개·광고 적용 전 각 사진의 이용 허락과 상업 이용 조건을 확인한다. 출처 표기만으로 허락이 확보되는 것은 아니다.
5. 토스 콘솔의 표시 이름을 `주말어디`로 맞추고 산출물을 업로드한다. QR 실기기 테스트와 재검토 제출은 별도 진행한다.
6. 토스 핵심 지표는 결과 보기(활성), 지도 열기(대표 전환)를 우선하고 공유·찜을 보조로 본다. 계측 예외가 앱을 막지 않는 보호 처리를 2026-10-01 AIT에 포함했다. 실기기 동작과 운영 이벤트 수집을 확인한 뒤 콘솔에 등록한다. 상세 이벤트와 AI 비용 집계는 `docs/MINIAPP_GROWTH_UX.md`를 참고한다.

# 주말어디 첫 웹 실험

## 범위와 비용

- 공개 웹은 사진 인트로 → 출발 기준 → 6문항 카드 → 선택 내용 확인 → 별도 결과 페이지 흐름이다. 서울·경기·인천의 13개 장소에서 브라우저 규칙으로 후보를 비교해 최상위 한 곳만 공개한다. 다른 후보 넘기기는 제거했으며 새 추천은 다시 6문항을 선택한다. AI, jbg 추천 API, 로그인, 결제는 호출하지 않는다. 광고는 승인 준비 상태가 기본이며 로컬에서는 요청하지 않는다. 현재 위치 권한은 사용자가 해당 버튼을 누를 때만 요청한다.
- 6문항은 JBG 원본 질문풀의 고정된 원천 3개(이동·동행·목적지)와 일반 3개(날씨·사진·휴식/활동)를 사용한다. 문구·선택지·태그·제약을 복사한 정적 사본이며 토스의 전체 질문풀을 무작위 배정하는 서버 정책과는 다르다. 미니앱에는 로컬 질문 fallback을 추가하지 않았다.
- 출발 기준은 ‘현재 위치로 추천’과 ‘지역 직접 선택’으로 나뉜다. 현재 위치는 브라우저가 받은 좌표를 그대로 사용하며 시청·권역 중심으로 대체하지 않는다. 지역 직접 선택은 미니앱과 동일한 전국 11권역·설명·대표 좌표를 사용한다. 지역 선택일 때만 대표 위치 기준 추정임을 표시한다. 관광공사에서 확인한 장소 좌표와 미니앱 서버의 직선거리 × 1.35, 45km/h 추정식을 사용한다. 실제 길찾기는 제공하지 않는다. 잘못된 권역/누락 좌표 및 해외·제주에서 본토까지의 자동차 이동 시간은 계산하지 않는다. 근교 선택은 왕복 120분 추정 이내, 실내 필수는 실내 가능 후보, 문화공간 선택은 편집 목록의 문화 분류를 지킨다.
- 전국 출발 권역을 선택할 수 있지만 여행지 목록은 여전히 수도권 13곳이다. 전국 관광지 검색과 관광공사 실시간 분류 검증을 추가한 것은 아니다. 이동 범위에 맞는 후보가 없으면 빈 결과와 출발지/선택 변경 버튼을 표시하며, 원점을 서울로 바꾸거나 먼 곳을 근교 결과로 반환하지 않는다. 빈 결과는 추천 성공 이벤트로 집계하지 않는다.
- 위치 권한 거부·미지원·실패·12초 시간 초과에는 지역 선택/재시도를 제공한다. 새 위치 요청·지역 선택·뒤로 가기·화면 이탈 후 늦게 온 응답은 무시한다. 좌표와 위치 정확도는 현재 메모리에만 보관하며 URL, browser history, 저장소, 공유 링크, 서버·이벤트에 넣지 않는다. 재시작·새로고침하면 지운다. 브라우저 위치는 [보안 연결과 명시적 허가가 필요하다](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition).
- 자연·사진·동행·휴식/활동은 선호 점수다. 이동·실내 조건 때문에 자연 선호가 덜 맞으면 근거와 주의 문구에 명시한다. 장소 특징과 운영 정보는 새로 생성하지 않는다. 공개 전 확인 화면에서 답변을 수정할 수 있고, 결과에서는 찜·공유·지도·새 조건 선택을 제공한다. 결과 페이지 복귀 시 원래 답변·GPS를 복구하지 않는다.
- `/recommendation/`으로 실제 문서 이동을 하므로 Offerwall의 조회 집계가 질문 화면의 hash 이동에 의존하지 않는다. 전달할 때 마지막 한 결과의 공개 장소 ID·근거·주의사항·출발 기준 명칭·추정 왕복 시간만 탭의 sessionStorage에 보관한다. 원래 답변·GPS·정확도·사용자/세션 식별자는 넣지 않는다. 열람 유효 기간은 30분이며 새 추천으로 덮어쓴다. 새로고침은 유효한 결과만 복구하고 완료 이벤트는 중복 전송하지 않는다. 저장소 차단 시 선택을 유지하고 허용 후 재시도하게 하며, 임시 결과가 없거나 만료되면 빈 페이지에 광고를 요청하지 않는다. URL에 개인 조건을 넣지 않고 검색 sitemap에서도 해당 경로를 제외한다.
- 광고 수익이 실제로 확인되기 전에는 웹 AI를 추가하지 않는다. 승인만으로 손익이 검증되었다고 보지 않는다. 도입 시 실측 AI 원가, 광고 실수령액, 호출 상한, 월 예산과 차단 장치를 별도 승인한다.
- AI 사용료는 발생하지 않지만 호스팅 트래픽과 이벤트 함수·로그 비용까지 무료라는 뜻은 아니다. 유료 플랜이나 예산 설정은 자동 변경하지 않는다.
- 웹은 토스 미니앱과 별도 실험이다. 미니앱의 현재 AI·광고·기존 이용권·프로모션 정책은 `MINIAPP_GROWTH_UX.md`를 따른다. 앱 식별자는 `wherego`, 표시 이름은 `주말어디`다.

## 첫 유입 실험

- 10개 상황별 글, 13개 장소별 공유 페이지와 sitemap을 제공한다. 순위·검색 유입·광고 승인은 보장되지 않는다.
- 공개 배포 및 검색 등록이 끝난 날부터 4주를 첫 관찰 기간으로 삼는다. 외부 유입이 거의 없으면 추천 품질보다 노출 경로가 아직 검증되지 않은 상태로 판단한다.
- 유입은 검색 노출·클릭, 활용은 지도 열기·저장, 확산은 공유 링크로 들어온 방문을 나누어 본다. 단순 공유 버튼 클릭을 실제 신규 유입이나 예약으로 집계하지 않는다.
- 첫 4주에 검색 클릭이 없으면 글의 검색 의도와 색인 상태를 점검한다. 방문은 있지만 지도·저장이 없으면 장소 구성과 결과 화면을 보완한다. 유입 표본이 적은 동안 유료 광고나 AI 비용을 늘리지 않는다.
- 직접 영업을 전제로 한 숙소 제휴는 범위에서 제외한다. 사용자가 2026-10-03 웹 AdSense와 공식 Offerwall 수익화를 요청했다. 계정·사이트 승인, 메시지 게시, 사진 이용 권한 확인은 코드 준비와 구분한다.

## AdSense와 Offerwall

- `robotupgrade.win`에서 사용 중인 공개 게시자 ID를 확인해 소유권 확인용 meta와 `/ads.txt`에 재사용했다. 게임의 광고 단위·도메인·계정 설정은 변경하지 않는다. 게임 배포 문서의 2026-09-30 기록에는 `주의 필요`/재검토가 남아 있으므로 계정 연결을 광고 승인 완료로 해석하지 않는다.
- [새 사이트는 AdSense 사이트 목록에 별도 추가해야 한다](https://support.google.com/adsense/answer/9131547?hl=ko). 기본 빌드는 확인용 meta/ads.txt만 생성하고 실제 광고 요청은 하지 않는다.
- 결과, 장소, 나들이 글의 실질 콘텐츠에만 광고를 연결한다. 질문·확인·빈 결과·개인정보·404·로컬/프리뷰에서는 요청하지 않는다. 선택·지도·찜 버튼과 광고 영역을 분리하고, 빈 광고·표시 실패는 콘텐츠 탐색을 막지 않는다. 광고를 임의 타이머로 갱신하거나 중복 요청하지 않는다.
- [일반 광고의 조회·클릭 보상은 허용되지 않는다](https://support.google.com/adsense/answer/48182?hl=ko). 반복 결과 조회는 [공식 Offerwall](https://support.google.com/adsense/answer/13866332?hl=ko)로 관리한다. AdSense의 개인정보 보호 및 메시지에서 주말어디 사이트를 선택하고 **포함 경로 `/recommendation/`**, **무료 첫 1페이지 이후 표시**, **보상형 광고 완료 후 추가 1페이지 권한**으로 설정·게시한다. 콘솔에서 기준점과 권한을 확인하고 무료 첫 조회/두 번째 조회를 실측한다. 정해진 빈도를 원하면 Google의 기준점 자동 최적화도 확인한다. 다른 글·장소·질문·약관은 제외한다.
- Google의 기준점은 방문자별 페이지 조회이며 미니앱의 매일 첫 무료 정책과 같지 않다. Google의 광고 수급·기존 권한·설정에 따라 Offerwall이 안 나올 수 있다. 코드가 매번 광고나 정산을 보장하거나 임의 시청 보상을 판정하지 않는다. [광고가 없으면 Offerwall 자체가 표시되지 않을 수 있다](https://support.google.com/adsense/answer/12726063?hl=ko).
- 광고를 켜기 전 사진의 상업 이용 허락, 사이트 `Ready`, 필요한 지역의 Google 인증 CMP/동의 메시지, Offerwall 게시를 확인한다. 일반 자동 광고는 질문 화면에 설치하지 않지만 결과 화면의 버튼 주변·전면 자동 광고도 콘솔에서 점검한다. 수동 배너는 새 반응형 광고 단위의 ID를 사용하며 게임의 고정 크기 단위를 무작정 복제하지 않는다. 슬롯이 없으면 수동 배너는 만들지 않고 AdSense 태그로 공식 메시지/콘솔 자동 광고만 사용한다.
- `scripts/weekend-monetization.mjs`의 기본값은 광고 비활성이다. 활성화는 빌드 환경의 `WEB_ADSENSE_ENABLED=true`, `WEB_MEDIA_COMMERCIAL_USE_CONFIRMED=true`를 명시해야 한다. 허용 호스트는 `WEB_ADSENSE_HOSTS`의 정확한 HTTPS 호스트 목록이며 기본은 `wherego-lake.vercel.app`다. `WEB_ADSENSE_DISPLAY_SLOT`은 선택 사항인 실제 반응형 광고 단위 ID다. 이번 작업은 운영 환경변수·계정·광고 단위를 설정하거나 공개 배포하지 않았다.
- Google 메시지가 준비되면 하단에 광고 개인정보 설정 진입점을 연결한다. 웹 개인정보 안내에 광고 쿠키/외부 정보 처리와 임시 결과 저장을 고지했다. 자체 DNT 계측 중단과 Google의 광고 개인정보 선택은 별개다.

## 계측의 한계

`/api/events`는 `visit`, `start`, `result_review`, `result_request`, `result`, `place_view`, `map`, `save`, `share`, `share_visit`와 유입 범주만 기록한다. 사용자·세션 ID, 답변, 정밀 위치, 원본 referrer는 보내지 않는다. DNT 사용자는 전송하지 않는다. `result_review`는 6선택 확인 진입, `result_request`는 결과 확인 버튼, `result`는 유효한 한 결과의 화면 준비다. Google 메시지 뒤에 가려진 결과를 실제 열람/광고 완료로 단정하지 않는다. Offerwall 표시·보상 완료·수익은 [Google 보고서](https://support.google.com/adsense/answer/12936184?hl=ko)에서 별도로 확인한다.

2026-10-01 보완: 같은 탭의 내부 이동에서는 세션 저장소에 유입 범주 하나만 유지한다. 검색에서 들어와 장소·지도·저장으로 이동해도 `search`를 유지하며, 공유 진입 후 내부 페이지 이동을 `share_visit`로 중복 집계하지 않는다. 검색 범주는 알려진 검색 호스트와 referrer로 추정하며 정확한 검색 클릭은 Search Console 등에서 확인한다. DNT 설정 시 범주 저장도 생략한다. 2026-10-03 이후 별도 결과 전달에는 세션 저장소가 필요하며 차단 시 답변을 유지한 재시도를 제공한다.

이 수치는 **이벤트 발생 수**다. 사용자 수, 재방문율, 사용자별 전환율로 해석할 수 없다. 여러 페이지를 열면 방문 이벤트가 여러 번 생기며 클라이언트 이벤트는 누락·조작될 수 있다. 호스팅 로그만으로 장기 보존과 정확한 퍼널 분석이 완성된 것은 아니다.

Vercel 로그 보존 기간 안에 해당 기간의 로그를 내보내고 다음 명령으로 집계한다. 입력은 한 줄당 JSON 형식이며 이벤트 JSON 자체 또는 `message`에 이벤트 JSON이 든 행을 지원한다. 다른 형식은 `ignored`에 포함되므로 실제 export 형식을 확인한다. 집계 출력에는 원시 로그를 포함하지 않는다. 중복 기간을 겹쳐 집계하지 않는다.

```powershell
node scripts/report-weekend-events.mjs C:\private-reports\weekend.ndjson
```

검색 유입 평가는 Google Search Console·네이버 검색 도구 등록과 권한 연결이 별도로 필요하다. 보존형 분석 서비스나 유료 custom events는 아직 연결하지 않았다.

## 실행과 검증

```powershell
yarn install --immutable
yarn web:build
yarn web:test
yarn web:dev
```

로컬 주소는 실행 출력의 URL을 사용한다. 기본 포트는 4173이며 사용 중이면 다음 포트를 쓴다. Playwright와 Chrome이 있는 환경에서는 `node scripts/verify-weekend-web.cjs`로 데스크톱·모바일, 모든 장소·글, 이미지, 저장·공유, 유입 범주 유지, DNT·저장소 차단, AI 요청 없음과 브라우저 오류를 검증한다. 필요하면 `WEB_BASE_URL`, `BROWSER_CHANNEL`, 외부 제공 Playwright의 `NODE_PATH`를 지정한다.

질문 원본 갱신은 최신 JBG 리소스 폴더를 명시해 `node scripts/sync-weekend-questions.mjs <wherego-resource-directory>`로 수행하고 생성된 `public/web/questions.mjs`를 검토한다. 원본 버전과 SHA256을 포함한다. 일반 웹 빌드는 JBG checkout·서버·환경변수 없이 이 사본을 사용한다. 6문항의 모든 64가지 답변 × 11개 출발 권역(704조합)을 회귀 검사한다. 지역 사본은 `node scripts/sync-weekend-origins.mjs`로 미니앱의 `regionOptions`를 AST 파싱하여 갱신한다. 미니앱 소스는 실행하거나 수정하지 않는다.

웹 빌드는 미니앱 `introPhotoData.ts`의 3개 JPEG를 AST로 읽어 그대로 복사하며 lucide-static의 아이콘 10개와 라이선스만 출력에 포함한다. 미니앱 화면·SDK·AIT는 변경하지 않는다. 공유 링크에는 공개 장소 ID만 넣고, 원래 답변과 현재 좌표는 메모리에만 보관한다. 별도 결과 페이지에는 위의 최소 임시 결과만 전달한다.
